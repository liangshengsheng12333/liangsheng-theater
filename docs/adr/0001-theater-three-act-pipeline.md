# ADR 0001: 凉笙歌剧院三幕式架构与双轨资产持久化规范

## 状态
已采纳 (Accepted) - 2026-10-09

## 背景与上下文
用户希望构建一个名为“凉笙歌剧院”的 Agent Skill，通过第一阶段深度需求探询与选角、第二阶段书籍与人物双向蒸馏（套用仓颉与女娲技能规范）、第三阶段人物登台进行沉浸式解决问题。

该方案涉及高强度的上下文开销、长文本提炼以及复杂的角色扮演深度，需要在流程控制、产物沉淀与交互角色方面做出关键技术权衡。

## 决策

1. **规模约束：严格 1 对 1 (单主角 + 单法典)**
   - 第一阶段限定为 1 位核心人物原型与 1 本核心经典法典，避免多角色多书籍导致的注意力稀释、人格漂移与蒸馏爆炸。
2. **资产策略：双轨制持久化 (通用 Skill 资产 + 专用推演剧本)**
   - 蒸馏出的人物心智（女娲范式）与书籍方法论（仓颉范式）均作为标准 Skill 持久化存入本地库，可无限次复用。
   - 每次特定任务另行生成一份包含现实场景与需求的《任务推演剧本 (Mission Script)》。
3. **流程关卡：白纸黑字文档门禁 (Gatekeeper)**
   - 第一幕结束前必须生成《排期简报 (Inquiry Brief)》并由用户明确批准后方可放行至第二幕。
4. **角色形态：心智原型叠加职责，先破冰对齐再登台推演**
   - 第三幕主角具备双重属性：【人物原有心智 (Who)】+【当期任务职责 (Stage Duty)】。
   - 登台初始必须严格按照其人设风格先与用户进行需求破冰对齐，再转入深入咨询与实战交付。

## 影响与后果
- **正面影响**：每次蒸馏不仅服务当前问题，还能不断丰富用户的私人“智囊团 Skill 库”；阶段责任清晰，避免因需求不明确导致的高额计算与 Token 浪费。
- **负面影响**：对自动开窗会话与跨会话数据传递的工程实现提出了较高要求。
