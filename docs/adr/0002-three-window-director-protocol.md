# ADR 0002: 物理三窗口总导演调度协议与三流派角逐机制

## 状态
已采纳 (Accepted) - 2026-10-09

## 背景与上下文
在确定三幕式流程后，需要落实具体的交互实现：
1. 如何兼顾第一幕的战略调度、第二幕的高负荷蒸馏与第三幕的纯净角色扮演长对话；
2. 如何在第一幕没有预设人选时提供高质量、具洞察力的选角候选；
3. 如何保证在缺乏本地语料时依然具备极强的信息提取能力。

## 决策

1. **三窗口总导演主从调度架构 (Director-Subagent Protocol)**：
   - **窗口 1（总控包厢）**：主 Agent 作为总导演，负责全程交互与调度；
   - **窗口 2（蒸馏工坊）**：第一幕放行后，总导演自动调用 `invoke_subagent` 拉起独立窗口 2，指示其执行书籍（仓颉体系）与人物（女娲体系）的双向蒸馏，蒸馏完成后向总导演发送完成汇报；
   - **窗口 3（大舞台）**：总导演收到汇报后，自动下发开窗指令拉起独立窗口 3，第三个窗口完成环境与角色加载后，宣布“大幕拉开”，开始与用户对话。
2. **三流派角逐赛 (Three-Stream Casting)**：
   - 第一幕调用 `deep-research` skill 针对用户核心问题进行跨领域搜索；
   - 必须产出 3 组代表不同哲学/战略视角的“人物 + 法典”组合矩阵（如：破局变革型、系统治理型、防守反脆弱型），由用户一键选定。
3. **自适应语料模式与深度搜索挂载**：
   - 优先读取本地工作区语料文件；若缺失，自动调用 `deep-research` 启动全网多源高密度检索（采访、演讲、论文、读书笔记），自动化提取蒸馏材料。
4. **两阶段登台演练与转场门禁 (Diagnostic Pivot Gate)**：
   - 第三幕由角色以原本心智与口吻切脉，出具诊断结论后主动请求转场，用户确认后切换为指定职务展开实战。

## 影响与后果
- **正面影响**：真正实现了三个窗口职责分离，杜绝会话污染；三流派矩阵极大降低了用户的决策门槛；自适应搜索让系统零门槛开箱即用。
- **技术要点**：需规范窗口 1 到窗口 3 之间的上下文交接数据包格式（Handoff Payload）。
